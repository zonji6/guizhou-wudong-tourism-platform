# 贵州乌冬文旅平台答辩演示流程

## 演示前准备

1. 在本机 `agent-service/.env` 配置 `DEEPSEEK_API_KEY`；如要展示知识检索和 LangSmith，再配置 `DASHSCOPE_API_KEY` 与 LangSmith 相关变量。密钥只留在本机，不写入仓库、页面或演示材料。
2. 启动 Docker Desktop，在项目根目录执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/start-demo.ps1
   ```

3. 打开 `http://127.0.0.1:5173`；在微信开发者工具中打开 `miniprogram` 目录，并关闭本地调试域名校验。
4. 演示中的商家、价格、库存和图片均为演示数据，答辩时主动说明。

## 建议讲解顺序（约 6 分钟）

### 1. 产品定位：贵州乌冬的苗族文化茶旅（40 秒）

从 PC 门户首页进入“苗族文化茶旅体验”。说明平台不是通用旅游模板：它围绕茶园、制茶/品茶、苗寨文化、在地餐饮与民宿，形成贵州乌冬的完整体验链路；衣食住行资源和社区攻略都围绕这一主轴服务。

### 2. 游客资源浏览（50 秒）

切换衣、食、住、行与文化体验分类，打开一项茶旅或民宿资源详情。强调页面同时呈现价格、标签、推荐理由与预约入口；所有未核验信息均已标示为演示数据。

### 3. AI 行程规划与来源（90 秒）

进入 AI 助手，输入：

> 我想体验贵州乌冬的苗族文化和茶旅，周末两个人，喜欢慢节奏。

展示“理解需求、检索资料、匹配资源、方案生成”的进度。展示生成的路线卡：茶园体验 → 制茶/品茶 → 苗寨文化 → 餐饮或民宿承接，并指出回答中的知识来源。

若未配置模型或向量服务，直接展示页面的降级提示，并继续演示资源浏览和预约闭环；不可把未配置状态表述成模型已经回答。

### 4. 待确认预约到正式订单（70 秒）

从路线或资源详情选择预约，填写日期、人数和联系人。先展示待确认信息，再点击确认。说明 AI 只能生成待确认预约，真正创建或确认订单始终由游客在页面确认、并由 Java 文旅服务写入业务数据。

### 5. 微信小程序一致体验（40 秒）

在微信开发者工具中展示同一条茶旅资源与 AI 助手入口，说明小程序与 PC 门户共用资源、订单和 AI API，但页面为移动端交互适配。

### 6. 管理后台与可观测性（70 秒）

进入后台：查看服务和知识内容，找到刚创建的订单并更新状态；随后打开 AI 运行轨迹，展示脱敏会话标识、LangGraph 节点、工具摘要、知识来源、耗时和最终状态。强调后台不展示模型思维链或 API Key；如果配置了 LangSmith，可补充开发期 Trace 已启用。

## 收束表达

本原型用 Java 固化资源和订单事实，用 LangGraph 管理 AI 快慢车道，用 RAG 为文化与茶旅回答保留来源；同时以“待确认预约”保证 AI 不会绕过用户直接生成正式订单。
