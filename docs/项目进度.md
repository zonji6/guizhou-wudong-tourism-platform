## 已实现的前端主链

### Web

1. 首次进入由用户点击开卷，不自动打开。
2. 首屏以“山、水、寨、茶、人”五联实景建立乌东身份。
3. 下滑经过雾散、叶片和沿溪入寨叙事，再进入服务与向导。
4. 乌东向导支持连续追问、阶段状态、当前/上一版结构化卡片、来源入口以及主动演示降级。
5. 推荐节点具备真实 `serviceId` 时才能进入详情和预约；预约由用户二次确认。

### 微信小程序

底栏固定为“首页｜游乌东｜向导｜寨里｜我的”。首页提供快速入口；“游乌东”浏览服务；“向导”承接连续咨询；“寨里”展示社区内容；“我的”查看已加入行程与订单。小程序以工具效率为先，不复刻 Web 长卷动效。

## AI 与数据能力边界

| 场景 | 可用状态 | 答辩表述 |
| --- | --- | --- |
| DeepSeek 已配置且调用成功 | 实时模型 | 可以说明本轮卡片由实时模型生成。 |
| DeepSeek 未配置或调用失败 | 主动演示降级 | 先显示真实错误；用户点击“查看演示结果”后才展示静态同构卡片，并持续标明“演示模式”。 |
| 云端 Embedding 未提供 | 关键词匹配降级 | 明确显示“关键词资料（演示）”，不得称为向量 RAG。 |
| LangSmith 未配置 | 不上传云端 Trace | 后台仍可展示本机脱敏运行摘要，但不能把它称为 LangSmith Trace。 |
| 商家、价格、库存等未核验 | 演示数据 | 只用于原型闭环，不代表真实可售资源。 |
| 照片授权未核验 | 本机素材 | 仅用于本机答辩演示，不进入公开发布素材范围。 |

## 后端后续计划

后端“五领域 v2”尚在计划阶段，后续将按已确认设计逐步完善领域模型、业务接口、订单边界、社区/路线能力和 AI 内部工具。当前不得把 v2 计划项写成已经上线，也不得用静态数据替代 DeepSeek、Embedding 或 RAG 的实现证据。

## 答辩前由用户确认

1. 按 [答辩演示流程](答辩演示流程.md) 完成一次六分钟人工前向演练。
2. 核对 DeepSeek、Embedding 与 LangSmith 的实际配置状态，并使用对应口径。
3. 确认推荐项的 `serviceId` 能贯穿详情、待确认预约、二次确认、订单查询和后台展示。
4. 检查演示页面没有历史误写、未声明的实时 AI/RAG 能力或未经脱敏的信息。
5. 在图片公开发布前另行完成来源与授权核验；未核验前仅在本机使用。
