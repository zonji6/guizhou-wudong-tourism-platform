# 贵州乌东文旅平台前端重设计规格

**状态：** 已由用户确认（2026-09-08）

**适用范围：** Vue 游客端、原生微信小程序、AI 向导界面，以及管理后台的品牌一致性

**目标：** 在三天答辩原型范围内，让用户先感知真实乌东，再顺畅进入衣食住行、社区、AI 行程与预约链路。

## 1. 规格效力与命名

本规格覆盖旧规格中的游客端视觉、首页结构、小程序信息架构和 AI 前端交互；Java、FastAPI、LangGraph、RAG、Redis、MySQL、WebSocket 与 LangSmith 的既有服务边界保持不变。此前生成的四栏小程序、中寨四景、全站悬浮叶片和概念插画首屏均为已淘汰探索稿；若与本规格冲突，以本规格为准。

产品对外名称统一为 **“贵州乌东”**。“乌冬”是历史误写，实施时必须从网页、小程序、管理后台标题、演示数据、错误提示和图片替代文本中移除。内部稳定的英文技术标识可继续使用 `wudong` 或 `udong`，不因中文名称修正而迁移数据库主键或接口路径。

品牌短句统一为 **“山静 · 人暖”**。它只在首页、小程序品牌区和加载空档低频出现，不作为每个页面的重复口号。

## 2. 体验目标与非目标

### 2.1 体验目标

1. Web 首页在首次访问时提供一次必须点击的开卷仪式，建立“与世隔绝、沿溪入寨”的进入感。
2. 首屏不依赖一张万能照片，而由“山、水、寨、茶、人”五联摄影素材共同建立乌东印象；其中地点与授权尚未核验的图片只能用于本机原型。
3. 前半段以实景和连续行走叙事建立地域真实性，后半段自然落到衣食住行、社区和 AI 服务。
4. 微信小程序采用工具优先结构，不照搬 Web 长卷；用户进入即可浏览、规划、查看社区和管理自己的行程。
5. AI 不只是聊天框。用户能看见可理解的协作阶段，并获得可查看、可加入、可预约的结构化行程。

### 2.2 非目标

- 不把 Web 做成通用景区相册、标准电商宫格或泛贵州宣传页。
- 不在小程序中复刻完整长卷、复杂雾效和桌面五联动画。
- 不新增真实支付、正式微信登录、地图导航、评价、积分、客服或生产级个人中心。
- 不为管理后台添加与操作无关的沉浸动画。
- 不引入动画框架；使用 Vue 过渡、CSS 和 `IntersectionObserver` 完成必要动效。

## 3. 视觉系统

### 3.1 情绪路径

页面从冷静的湿润山色出发，经过溪流、木楼与茶垄，最后抵达人物、火塘和饭桌的暖色。不是全站统一套一层复古滤镜，而是用色温变化表达“山静 → 人暖”。

### 3.2 色彩令牌

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 湿山深绿 | `#173F36` | 主背景、导航、主要按钮、卷轴暗部 |
| 溪石青 | `#86A69D` | 水景状态、次级背景、信息连接线 |
| 雾纸白 | `#F2EFE5` | 正文背景、卡片和留白 |
| 老木褐 | `#684C3A` | 卷轴轴杆、木楼章节、边框 |
| 火塘铜 | `#C6734D` | 人文段落、确认动作和少量强调 |
| 茶芽金 | `#D8CB86` | “一叶同行”、当前进度与仪式焦点 |

火塘铜不作为全站通用高亮色；它只在叙事进入人物与确认预约时出现。这样可避免页面退化为常见的米白加陶土色模板。

### 3.3 字体

- 仪式标题、场景题签：`STKaiti, KaiTi, "楷体", serif`，只用于短句和大字。
- 页面标题、故事标题：`"Noto Serif SC", "Source Han Serif SC", STSong, SimSun, serif`。
- 正文与操作：`"Microsoft YaHei", "PingFang SC", sans-serif`。
- 数据、状态与英文小字：`Inter, "Segoe UI", Arial, sans-serif`。

不新增大型在线字体依赖；本机无法命中首选字体时按上述字体栈降级。

### 3.4 唯一视觉签名

唯一高辨识度签名是 **“开卷后的五联实景 + 一叶同行”**。苗族纹样只允许作为不承载事实信息的低频细线、压纹或分隔，不使用未经核验的具体图腾，不再叠加第二套抢眼装饰。

## 4. Web 首页体验

### 4.1 首次开卷

- 首次进入当前浏览器会话时显示闭合卷轴，使用 `sessionStorage` 键 `wudong:scroll-opened` 记录本会话状态。
- 中央唯一主操作为“点击这里”，下方小字“开启画卷”。必须点击才开始，滚轮、自动计时和悬停都不能代替用户操作。
- 闭合门面无雾，用户可以完整看见卷轴。两侧只使用山脊、溪线、茶叶和木纹等低密度原创图形。
- 打开后的品牌说明固定为“走进雷公山半山的乌东苗寨”，不再并用“古寨秘境”“世外桃源”等泛化或异域化表述。
- 卷轴向左右退出，五幅实景按 70～90 ms 间隔显现，总时长控制在约 1.4 秒。
- 同一浏览器会话返回首页时保持已打开；关闭浏览器后再次访问重新出现仪式。
- 开启“减少动态效果”时仍需点击，但只执行约 180 ms 淡入淡出。

### 4.2 五联实景

桌面端五联默认等宽，顺序固定为：

| 场景 | 本机原型图片 | 默认作用 |
| --- | --- | --- |
| 山 | `天光乍雾山.jpg` | 建立湿润中山、安静与纵深 |
| 水 | `风雨桥.jpg` | 建立溪流、桥与村寨关系 |
| 寨 | `乌东苗寨.jpg` | 以原图“乌东苗寨 / WuDong Miao Village”文字作为身份题签 |
| 茶 | `采茶.png` | 聚焦采茶人物、手部动作和茶叶 |
| 人 | `老幼相宜——人间幸福.jpg` | 以自然笑声把冷山色过渡到人的温度 |

鼠标或键盘聚焦某联时，只做轻微横向舒展；离开后恢复等宽。点击或按回车后，当前场景打开为近全屏探景层。移动 Web 不强行保留五个窄栏，改为“一张主卡 + 两侧露出相邻卡”的横向吸附浏览。这里确认的是构图和摆放，不代表图片地点、著作权或肖像授权已确认。

图片必须使用独立的桌面和移动焦点值，不能全部依赖 `object-position: center`。具体焦点、候选图、条件使用图和禁用图以 [贵州乌东视觉素材编排](../../贵州乌东视觉素材编排.md) 为准。

### 4.3 点击探景

桌面使用约 `92vw × 88vh` 的近全屏层；移动端使用全屏页面。打开和关闭不丢失首页滚动位置，并支持遮罩点击、关闭按钮与 `Escape` 返回。

每景只包含一段短故事和一个主行动：

| 景 | 故事方向 | 唯一主行动 |
| --- | --- | --- |
| 山 | 山路、雷公山湿润中山环境 | 查看山野路线 |
| 水 | 溪流、风雨桥、沿水入寨 | 开始沿溪漫游 |
| 寨 | 木楼、村落空间和村寨导览 | 查看村寨导览 |
| 茶 | 采茶、制茶、品茶与待客 | 进入茶旅体验 |
| 人 | 日常劳作、饭桌与寨里故事 | 看寨里人物故事 |

不在探景首层堆叠价格、时长、库存等交易参数。服务信息在用户点击主行动后进入现有资源与详情页。

### 4.4 下滑叙事

首页顺序固定为：

```text
开卷门面
→ 五联实景
→ 山雾短暂经过
→ 茶坡与溪流
→ 风雨桥和木楼
→ 人物、劳作与相聚
→ 衣食住行服务
→ 完整 AI 行程工作台
```

雾只出现在用户从五联继续下滑时，作为“观看 → 行走”的边界。雾层设置 `pointer-events: none`，不可长时间遮挡图片或正文，不拦截正常滚动，也不出现在首次门面。“沿溪入寨”只是页面叙事名称，在路线、安全和开放情况核验前不得表述为官方游览线路。

茶垄的线条在下一段转成溪流路径，内容节点沿这条路径出现；桌面可形成不完全对称的沿溪布局，移动端退化为清晰的单列顺序。衣食住行仍是真实可点击入口，但视觉上表现为沿溪分布的节点，不使用标准四张同尺寸商城卡片作为首页主结构。

## 5. “一叶同行”与 Web AI

“一叶同行”是茶叶轮廓与溪流叶脉组合的抽象生命体，不拟人化为未经文化核验的苗族角色。

- 开卷门面和五联首屏不出现 AI 悬浮入口。
- 用户首次向下滚动、雾层散开后，叶片沿短溪线轻轻落下并成为右下角随行入口。
- 待机状态只做幅度不超过 3 px 的低频呼吸；收到消息时叶脉出现一次水纹反馈。
- 点击叶片进入 Web AI 工作台；首页后段同时提供完整 AI 区域。
- `prefers-reduced-motion` 下取消飘落和呼吸，只执行静态淡入。

## 6. AI 对话工作台

Web 与小程序共享相同的信息模型，布局分别适配宽屏和手机。

### 6.1 页面组成

1. 对话区：输入旅行需求、使用示例问题、追加或修改条件。
2. 四段状态条：需求理解 → 知识检索 → 服务协同 → 行程生成。
3. 结构化结果区：按天展示路线、时间段、资源、来源和下一动作。
4. 操作区：查看详情、加入行程、发起待确认预约。

进入一次可见工作台会话时只生成一个 `thread_id`，同一次会话内的追问和条件修改都复用该标识，并保留消息与“上一版”结果。本期不增加历史会话中心或跨设备同步；若服务端未保存上下文，界面不得宣称已经理解前文。

前端只根据 WebSocket 真实事件推进状态，不伪造模型思维过程。`node_started`、`tool_finished` 和 `card_ready` 被映射为用户能理解的短句；某阶段未发生、被跳过或失败时如实显示，不能用定时器假播放。特别是“服务协同”只在真实资源服务调用发生时点亮，不能为了四格齐全虚构 Agent 或工具执行，也不显示没有可靠依据的剩余秒数。

游客端不得展示提示词、原始思维链、内部消息、未脱敏工具参数、联系人信息、模型名或 LangGraph 等实现术语；这些内容只进入答辩架构说明。

### 6.2 卡片与来源

- 行程卡片按天分组，每天保留主题、节点顺序、简短理由和服务入口。
- 两端按真实 `AgentCard` 契约读取 `type`、`title`、`summary`、`data` 和 `sources`；分日行程读取 `data.days`，来源只读取 `sources[].title`。支持类型固定为 `itinerary`、`service_recommendation`、`knowledge_answer`、`clarifying_question`、`pending_booking` 和 `error`，演示数据也必须保持同构，不能继续使用只存在于旧页面的 `text/items` 结构。
- 知识来源默认折叠为“参考了 2 条乌东资料”，展开后显示标题，不显示内部存储键；数量必须来自实际来源数组。
- 用户调整条件时保留已有对话，但旧行程明确标记为“上一版”，新结果完成后再替换主结果。
- “查看详情”“加入行程”和“预约”只能使用卡片返回的真实 `serviceId`；没有标识时隐藏相应动作，禁止用固定演示编号冒充。AI 只能创建待确认预约；用户仍需在独立确认页核对日期、人数与联系人。
- 高山茶旅时长、人数、价格、住宿和饭食等尚无服务台账支撑的信息必须标为“示例”；未接入实时数据时统一提示“请以服务方确认结果为准”，不承诺可预订、开放时段或库存。

### 6.3 失败与演示降级

- WebSocket、模型或检索不可用时显示明确错误卡片，并保留资源浏览、社区和订单能力。
- 若启用本地演示回退数据，卡片全程持续显示“演示模式”，不能把静态结果伪装成 DeepSeek、RAG 或服务工具实时执行，也不能在断线后由定时器自动宣称“方案已生成”。
- 图片加载失败时显示对应场景色块、名称和替代文本，不显示浏览器破图图标。

## 7. Web 其他页面与管理后台

### 7.1 游客端页面

现有资源、详情、社区、AI、预约路由继续保留。顶栏在开卷完成后出现，最少包含“贵州乌东”“游乌东”“寨里”“乌东向导”和“运营后台”。AI 主行动文案统一为“为我安排乌东之行”，不再并用“AI 游乌东”“AI 行程助手”等游客端名称。资源列表与详情使用统一摄影素材、焦点元数据和“演示数据”标识。

### 7.2 管理后台

管理后台不使用卷轴、雾效、五联或叶片呼吸动画。它只复用湿山深绿、雾纸白、火塘铜和字体层级，继续以订单、内容和 AI 脱敏运行摘要为核心。后台所有“乌冬”文案同步修正为“乌东”。

## 8. 微信小程序

### 8.1 定位

小程序采用 **工具优先**：打开即看到常用服务、当前行程和 AI 入口，不强制播放 Web 开卷，不复制复杂雾效。顶部保留一块短小的乌东实景与“山静 · 人暖”，随后直接进入可操作内容。

### 8.2 五栏导航

使用自定义底部导航，固定为：

```text
首页｜游乌东｜向导｜寨里｜我的
```

- “向导”位于中央，以“一叶同行”为按钮主形态，进入现有 AI 页面。
- 小程序不再另设全局悬浮叶片，避免一个功能出现两个入口。
- “游乌东”承接现有资源列表；“寨里”承接社区；“我的”为最小个人页，只展示演示身份、我的行程与预约订单入口。
- 详情、预约确认和订单详情是二级页面，不占底栏位置。
- 本期不实现微信授权登录、头像上传、收藏、积分或复杂账户设置。

自定义底栏在 `app.json` 使用 `tabBar.custom: true`，五个主栏 `pagePath` 固定为 `pages/index/index`、`pages/resources/resources`、`pages/assistant/assistant`、`pages/community/community`、`pages/profile/profile`。主栏切换使用 `switchTab`；只有详情、预约确认和订单详情使用二级导航。首页带分类意图进入“游乌东”时，先保存一次性筛选意图，再切换主栏，不通过错误的 `navigateTo` 传参。

### 8.3 小程序首页

首屏优先展示“今天，想怎么游乌东？”与茶旅、食宿、路线、导览入口；衣食住行可在首屏一跳进入。若存在未完成行程或预约，显示“继续上次行程”；没有时显示“让向导为我安排”。实景只做紧凑品牌层，不压过操作入口。

### 8.4 小程序 AI

采用已确认的 **对话工作台**：顶部是短对话，中部显示四阶段进度，结果以分日卡片向下生长，底部输入框固定。点击“查看详情”“加入行程”或“预约”进入相应原生页面。“加入行程”本期只保存单设备、单会话演示状态，并在“我的”显示，不扩成账户同步或协作行程。

## 9. 前端模块边界

### 9.1 Vue

`App.vue` 只保留顶层路由选择、共享数据和游客端/后台壳层。首页拆成职责明确的组件：

- `ScrollGate`：会话状态、点击开卷和减少动态效果。
- `FiveSceneHero`：五联布局、焦点、键盘操作和点击事件。
- `SceneExplorer`：近全屏故事层与单一主行动。
- `WudongJourney`：雾转场、沿溪叙事和服务节点。
- `LeafGuide`：出现时机、入口状态和动效降级。
- `AssistantWorkspace`：WebSocket 状态、对话和结构化卡片。

不为此次改造引入 Vue Router；继续使用现有 hash 路由，避免三天原型范围扩张。

### 9.2 素材元数据

五联和故事段不在模板中散落硬编码路径。使用一个小型素材清单记录：`id`、`src`、`alt`、`desktopFocus`、`mobileFocus`、`expandedAsset`、`sourceStatus`。Web 与小程序使用相同语义标识，但各自引用适合体积的派生图片。

“山、水、寨、茶、人”只属于首页叙事维度，不新增后端分类、数据表或 CMS。现有衣食住行业务分类继续映射为 `culture`、`food`、`stay`、`travel`，只调整游客端名称与排序。

### 9.3 小程序

保留现有 `index`、`resources`、`assistant`、`community`、`orders`、`detail` 和 `booking` 页面；新增最小 `profile` 页面和自定义底栏。页面逻辑不重写为跨端框架。

## 10. 素材与内容边界

- 本机原型的首屏构图已确认使用《天光乍雾山》《风雨桥》《乌东苗寨》《采茶》《老幼相宜——人间幸福》；这不等于地点或公开授权已经确认。对外替代文本和界面题名使用中性、具体的描述。
- 《乌东苗寨》原图文字按用户决定保留，并承担身份题签；同一区域不再叠加第二个大标题。
- 《村寨全景航拍》用于点击展开与“一寨一谷”，不再占五联默认“寨”位。
- 梯田不能被写成茶园；明确属于其他寨子、喀斯特峰林或侗寨鼓楼的图片不作为乌东实景。
- 每张发布图片必须记录作者、原始链接、拍摄时间和地点、授权范围、署名要求以及是否允许裁切或二创；政府或媒体报道中出现不等于可商用。含清晰人脸、民居内部、商户、服饰或仪式的素材还需对应主体或场景许可；含未成年人的《老幼相宜——人间幸福》必须取得监护人许可。裁掉水印不等于获得授权。
- 用户提供的图片可用于本机设计和答辩比稿；在来源许可补齐前，不自动提交到公开 GitHub 仓库。
- 概念插画若作为过渡使用，必须标为“概念示意”，不得称为“乌东实景”。火塘在取得真实素材和服务核验前只保留为待补氛围方向，不宣传为已存在或可预约体验。

## 11. 可访问性与性能

- 所有场景都能通过键盘聚焦、回车打开和 `Escape` 关闭；焦点轮廓不可只靠颜色差异表达。
- 图片具有描述性 `alt`；纯装饰雾层和纹样对辅助技术隐藏。
- 正文、按钮和状态满足清晰对比；不在雾、天空或复杂纹样上直接压低对比文字。
- 派生 Web 图片优先使用 WebP/AVIF，并保留兼容格式；小程序使用更小尺寸，不重复打包原始大图。
- 本机答辩不再依赖 Unsplash 图片或 Google 在线字体；照片使用已确认的本地派生图，字体使用第 3.3 节的本机字体栈。
- 首屏只预加载五联缩略资产；近全屏图和下滑图片延迟加载。
- 动画只改变 `transform` 与 `opacity`，避免高频布局抖动；所有核心内容在禁用动画后仍可访问。

## 12. 三天原型范围

### 必须精做

1. Web 点击开卷。
2. Web 五联实景、轻舒展和点击探景。
3. Web 下滑雾转场与“一叶同行”出现。
4. Web 和小程序 AI 对话工作台的四阶段状态与行程卡。
5. 小程序五栏导航及“我的”最小页。
6. 现有资源详情、预约确认、订单和后台闭环保持可进入。

### 只做清晰可用

- 资源列表、社区列表、服务节点、管理后台表格。
- “我的”中的演示身份和订单/行程入口。
- 非主链路图片加载、空状态和错误卡片。

### 明确延后

- 每个段落的独立复杂动画、地图动画、天气联动、视频背景。
- 真实账户体系、收藏、评论、社交关注和支付。
- 为所有服务准备完整商业级摄影素材。

## 13. 用户验收清单

实施完成后由用户按以下可见行为验收：

1. 新浏览器会话必须点击“点击这里”才开卷；同一会话返回首页不重复。
2. 门面无雾，向下滚动后才出现短暂雾转场。
3. 五联顺序、图片和题签为“山、水、寨、茶、人”；“寨”保留原图文字，“茶”使用《采茶》。
4. 五联可轻微舒展，点击后进入近全屏故事，并能返回原滚动位置。
5. Web AI 叶片只在雾散后出现。
6. AI 页面显示四个可理解阶段，并输出带来源和服务入口的分日行程。
7. 小程序进入即见功能，底栏为“首页、游乌东、向导、寨里、我的”，中央向导使用叶片形态。
8. 预约仍需用户二次确认，后台可进入订单与脱敏轨迹页面。
9. 所有用户可见中文统一为“贵州乌东”，演示或降级内容有明确标识。
10. 同一 AI 工作台中连续追问不会更换线程或清空对话；缺少真实 `serviceId` 的结果不显示详情或预约动作。

## 14. 测试与验证约定

本规格不新增自动化测试文件，不要求运行全量、回归或测试矩阵。后续实现计划不包含未经用户要求的测试任务。若用户另行指定验证场景，只执行指定范围；页面最终是否符合氛围、文案与交互预期，以第 13 节的用户可见验收为准。
