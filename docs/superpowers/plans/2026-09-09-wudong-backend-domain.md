# 贵州乌东后端领域与 AI 服务实现计划

**状态：** 用户已确认（2026-09-09）；本轮补充决策已确认，对应实现尚未开始。

**跨端需求修订：** 用户已确认 Web 与小程序的个人行程、AI 草稿和订单需要互通，并选择轻量账号密码，两端登录同一平台账号。下文匿名 `visitorId` 与归属字段为旧基线；实施前须根据后续确定的账号创建与会话方案修订凭据校验、归属查询、迁移和契约，不能仅凭 UUID 格式或共享固定演示身份放行。此选择不等于确定会话技术或批准迁移旧数据，不增加商家账号或完整注册找回体系，详见整合开发文档第 4.1、5.3 节。

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 建立分领域目录、三类订单、轻量社区/路线攻略、匿名访客边界和可恢复的 LangGraph AI 服务。

**架构：** Java 是目录、订单和社区的唯一写入口；Python 通过内部 API 读取资料并只创建餐食/住宿待确认单。当前先支持水彩虚拟示意地图的地点引用、固定相对节点和连线；真实地图底图与路径服务在具备服务商访问方式、授权和已核验坐标后接入。

**技术栈：** Java 21、Spring Boot、JdbcTemplate、Flyway、MySQL、Python 3.11、FastAPI、LangGraph。

### 任务 3：实现三类订单与匿名访客边界

**文件：** 修改 Java repository/service/controller；创建各订单请求与响应记录。

- [ ] 从 `X-Visitor-Id` 读取并格式校验匿名标识；订单和社区写接口拒绝缺失或无效标识。
- [ ] 商品订单校验数量和取货点，初始为待取货；餐食订单校验同店明细、份数、共享到店时间与人数，初始为待到店；住宿预约校验 `checkInDate`、`checkOutDate`、`roomCount`、`peopleCount`，初始仍为待确认。
- [ ] POST `/api/food-orders` 接受 `merchantId, items:[{foodItemId, quantity}], visitAt, peopleCount, contactName, contactPhone, note, sourceThreadId`；Java 校验明细非空、份数为正整数、全部条目属于指定店铺且已上架，混店整单拒绝。
- [ ] Java 按目录中明确的模拟单价计算每行金额与合计，保存名称、单位、单价、数量、行金额及合计快照；`food_order` 与全部 `food_order_item` 在同一事务写入，拒绝时不保留部分主单或明细，不信任客户端报价。
- [ ] 住宿离店日期必须晚于入住日期，房间数和人数为正整数，夜数由日期计算；原始参考价格/容量与模拟值分别保存，仅有明确模拟计价单位和口径时才计算演示金额，不实现实时房态、动态价格或库存锁定。
- [ ] `/api/me/*` 仅按当前访客读取订单；后台读取订单时不向游客端回传联系人信息。
- [ ] 状态更新逐类型白名单校验，拒绝跳跃和不属于该订单的状态；餐食整单仍为 `PENDING_VISIT → COMPLETED / CANCELLED`，不新增逐菜状态、跨店购物车、支付、配送、退款或实时库存。
