**状态：** 用户已确认（2026-09-09）；本轮补充决策已确认，对应实现尚未开始。

**跨端需求修订：** 用户已确认 Web 与小程序以同一平台账号共享个人行程、AI 草稿和订单，采用用户名密码及 Spring Security + JWT。最简自助注册为必填用户名、密码和可选昵称，暂不接短信或邮箱验证。公共内容免登录；保存行程或草稿、提交订单、发布社区和查看个人记录需登录，登录后返回原操作、保留本次输入但不自动提交订单。下文本地 `visitorId`、匿名访客任务及“不做登录”表述保留为旧基线，不能直接作为最终实现或验收要求；先细化会话传输与失效规则，再修订两端 API 和我的页面。游客顶栏右侧改为“我的”，后台入口移出，仅供授权开发和运营使用。角色已确认仅分游客与后台管理人员，开发者和运营者各用独立账号、共用一档既定后台业务权限；管理账号创建待讨论，不增加复杂权限配置、完整找回体系或商家登录，详见整合开发文档第 4.1、5.3、5.4 节。

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 在已批准的沉浸首页与乌东向导之外，实现“逛乌东”总览、商品、食、住、行、社区、三类确认订单、我的订单和运营后台。

**架构：** Web 保留 Vue hash 路由，小程序保留原生页面；两端通过同一领域 API 与本机 `visitorId` 读取数据。当前 `2026-09-08-wudong-frontend-redesign.md` 正在并行实施，本计划只能在其页面拆分完成并合并后执行，不能并发修改 `App.vue`、首页或向导工作台。

**技术栈：** Vue 3、Vite、原生微信小程序、现有 Java REST API、水彩虚拟示意地图；真实地图服务商 SDK 后续再接入。

## 实施约束

- 不新增或运行自动化测试；每任务以用户可见手工验收与 API 契约核对作为检查。
- 所有未核验资料、地图数据、价格、库存与图片显示演示标识。
- 缺少的价格、容量等业务数据可补充为本机演示样例，与原始参考值分列；不以等待真实业务样本核验阻塞本机开发。
- 餐食以 `merchant` 为店铺归属，只提供同店菜单多选与店内选餐篮；不做跨店购物车、逐菜状态、支付、配送、退款或实时库存。后台仍由集中运营按店管理，现须增加开发和运营人员的登录授权；不增加商家账号或商家权限体系，也不扩展评论、点赞或图片上传。

### 任务 1：建立匿名访客与领域 API 边界

**文件：** 修改 `web/src/services/api.js`、`miniprogram/utils/api.js`、`miniprogram/app.js`；创建 `web/src/composables/useVisitorId.js`。

- [ ] 生成 UUID 格式的 `visitorId`，Web 保存于 `localStorage`，小程序保存于 `wx` storage；不得使用手机号、设备硬件 ID 或固定演示编号。
- [ ] 每个订单/社区写请求发送 `X-Visitor-Id`；我的订单只调用 `/api/me/*`，不拼接手机号查询参数。
- [ ] 定义领域调用：商品、食、住、地点、动态、三类订单与后台资源；失败时返回“服务暂不可用”，不把本地假数据冒充为服务成功。
- [ ] 手工检查：刷新浏览器或重启小程序后 `visitorId` 不变；不在界面或控制台显示其值。

### 任务 2：实现 Web 逛乌东、商品、食、住与确认闭环

**文件：** 创建 `web/src/pages/ExplorePage.vue`、`CatalogPage.vue`、`CatalogDetailPage.vue`、`OrderConfirmPage.vue`、`MyPage.vue`；修改已拆分后的路由壳与公共样式。

- [ ] 总览固定为茶旅引导、五张模块卡、一条演示推荐和继续行程入口；首页快捷卡及顶部“逛乌东”复用相同路由目标。
- [ ] `CatalogPage` 按 `product`、`food`、`stay` 映射标题、筛选字段及数据源；卡片只显示对应价格、标签、演示标识和详情入口。
- [ ] 详情页按类型只显示一个主动作：商品数量/取货点后下单，餐食进入所属 `merchant` 的菜单多选菜品/饮品/套餐并调整份数后确认，住宿填写入住日期 `checkInDate`、离店日期 `checkOutDate`、房间数 `roomCount` 和人数 `peopleCount` 后预约。
- [ ] 餐食店内选餐篮只容纳同一家店的条目，提交时明细非空，份数为正整数；汇总为一张到店订单，共享到店时间、人数、联系人和备注。POST `/api/food-orders` 使用 `merchantId, items:[{foodItemId, quantity}], visitAt, peopleCount, contactName, contactPhone, note, sourceThreadId`，价格与金额由 Java 重新核对计算。
- [ ] 餐食确认页列出店铺、每项名称/单位/模拟单价/份数/行金额和合计，保持模拟标识；创建后我的订单使用 Java 返回的主单与明细快照，不从当前菜单重算历史订单。Java 负责同店、上架、份数校验和金额计算，混店整单拒绝。
- [ ] 住宿要求离店日期晚于入住日期，房间数和人数为正整数；由日期计算夜数，仅在明确模拟计价口径时展示演示金额，仍由后台确认，不承诺实时房态、动态价格或库存锁定。
- [ ] 确认页在 POST 前列出资源、字段和联系人；成功后跳转我的订单，不提供支付或跨访客订单查看。
- [ ] 手工验收：商品、住宿各完成一条“列表→详情→确认→我的订单”路径；餐食完成“餐馆→同店菜单多选/调整份数→整单确认→我的订单”，核对一张订单包含全部明细。
